1. エグゼクティブサマリー

背景

DApps（分散型アプリケーション）の運営において、秘密鍵の管理はセキュリティの根幹をなす最重要課題である。2025年2月のBybitハック（約14億ドルの被害）に代表される大規模インシデントは、単一の秘密鍵管理に依存する危険性を改めて浮き彫りにした。本レポートでは、MPC（マルチパーティ計算）、HSM（ハードウェアセキュリティモジュール）、スマートコントラクトマルチシグ、クラウドKMSなど異なるアプローチを採用する10のソリューションを、7つの評価軸で多次元比較し、DApp運営者に最適な鍵管理戦略を提案する。

各候補の特徴紹介

Fireblocks MPC

MPC-CMP（マルチパーティ計算）とIntel SGX/TEE（信頼された実行環境）を組み合わせた、機関投資家向け暗号資産インフラのリーダー。1,800以上の機関が利用し、累計$10兆超の資産を処理。80以上のブロックチェーンに対応し、DeFiプロトコル連携やガバナンス機能も統合。SOC 2 Type II取得。

BitGo MPC

2013年設立のデジタル資産インフラの老舗。マルチシグとMPCの両方をサポートし、Assets on Platformは$104B超。2026年にIPO準備中との報道あり。OCC（通貨監督庁）認可の信託会社であり、米国の規制に準拠した唯一のカストディソリューションの一つ。600以上の機関が利用。

Safeheron MPC

MPC-TSSとTEEを組み合わせた鍵管理をオープンソースで提供する稀有なプロバイダ。セルフカストディとSaaSの両方に対応し、170以上の機関が利用。累計$15.1Mの資金調達。無料スタータープランがあり、中小規模のDApp運営者にとってエントリーしやすい。

Turnkey TEE

AWS Nitro Enclavesベースの信頼された実行環境（TEE）で秘密鍵を保護するWallet-as-a-Service。50〜100msの高速署名と$0.01〜$0.10/署名の低コストが特徴。5,000万以上のウォレットを管理。パスキー認証に対応し、エンドユーザー向けの組み込みウォレットにも最適。YC出身でSeries Aまで$18.5M調達。

Dfns MPC

MPC、HSM、TEEを柔軟に組み合わせた「Key Orchestration Service」を提供するWaaSプラットフォーム。SaaS/ハイブリッド/フルオンプレミスの3つのデプロイモデルに対応。IBMの「Digital Asset Haven」のコア技術パートナー。Fidelity International、ABN AMROなど金融機関を含む324社が採用。SOC 2 Type II + ISO 27001取得。累計$29.5M調達。

AWS KMS + CloudHSM Cloud KMS

FIPS 140-3 Level 3認証済みHSM上でsecp256k1をネイティブサポートするAWSのフルマネージド鍵管理サービス。IAM/CloudTrailによる堅牢なアクセス制御と監査機能を標準提供。月額$1〜$16の圧倒的な低コスト。CloudHSMは専用テナントで最大7,000 ops/secのスループット。BYOK（鍵インポート）にも対応。

GCP Cloud KMS Cloud KMS

Safe（旧Gnosis Safe） スマートコントラクト

EVM互換チェーン上で動作するスマートコントラクトベースのマルチシグウォレット。M-of-N閾値署名でトランザクションを承認・実行し、$600B超の資産を保全する業界標準。Ethereum Foundation、Uniswap DAO、Aave等200+プロジェクトが採用。ERC-4337/パスキー認証にも対応。無料で利用可能。

OpenZeppelin Defender 運用プラットフォーム 終了予定

スマートコントラクトの運用・監視・自動化を統合提供するSaaSプラットフォーム。Relayerによる鍵管理とトランザクション自動化、Monitorによるオンチェーン監視、Safe統合のガバナンス管理を提供。Compound/Aave等が採用。ただし2026年7月にサービス終了が確定しており、新規採用は非推奨。OSS版への移行が進行中。

HashiCorp Vault セルフホスト

汎用シークレット管理の業界標準。Shamir's Secret SharingによるSeal/Unsealメカニズムと、Transit Secrets Engineによる「Encryption as a Service」を提供。Ethereumプラグインでsecp256k1署名に対応するが、主要プラグインが約4年間メンテナンスされていない点が最大の懸念。2024年にIBMが$6.4Bで買収。セルフホストの運用複雑性が高い。

3.2 アーキテクチャ別の特徴

MPC（マルチパーティ計算）

秘密鍵を複数のシェアに分割し、各シェアを異なるノードで保管。署名時に完全な秘密鍵を再構築せずに分散的に署名を生成。単一障害点の完全排除が最大の利点。Fireblocks（MPC-CMP）、Dfns（KU23）、Safeheron（MPC-TSS）がそれぞれ独自プロトコルを実装。

HSM（ハードウェアセキュリティモジュール）

FIPS認証済みの耐タンパーハードウェア上で鍵を生成・保管・使用。鍵はHSM外にエクスポート不可。AWS KMS（FIPS 140-3 L3）、GCP Cloud KMS（FIPS 140-2 L3）が代表例。規制要件への適合が最大の利点。ただしブロックチェーン固有機能は提供しない。

TEE（信頼された実行環境）

CPU内の隔離された実行環境（Intel SGX、AWS Nitro等）で鍵操作を実行。OSやハイパーバイザからもアクセス不可。Turnkeyが純粋TEEアプローチを採用。Fireblocks、DfnsはMPCとTEEの組み合わせでさらに堅牢化。高速な署名処理が可能。

スマートコントラクトマルチシグ

オンチェーンのスマートコントラクトがM-of-N署名の検証と実行を管理。Safeが事実上の標準。トラストレスかつ透明性が高いが、各署名者の秘密鍵管理は別途必要。Bybit事件はスマートコントラクトの脆弱性ではなくUI層の侵害だった点に留意。

重要インシデント: Bybitハック（2025年2月）

約$1.4Bの被害。Safe{Wallet}開発者のマシンが北朝鮮Lazarusグループにより侵害され、UIに悪意あるJavaScriptが注入された。署名者が見ている画面と実際のトランザクション内容が異なるように改ざんされ、マルチシグの全署名者が騙された。教訓：マルチシグでも署名者全員が騙されれば防御不能。トランザクション内容の独立検証が必須。

7.1 推奨アーキテクチャ: 多層防御モデル

Safe（マルチシグ）+ MPC/HSM（各署名者の鍵保護）

10.2 ユースケース別推奨

1 エンタープライズ / 大規模DApp運営

2 中規模DApp / DAOトレジャリ管理

推奨: Safe + AWS KMS

Safe のマルチシグをメインのガバナンスレイヤーとし、各署名者がAWS KMSで鍵を保護。月額$2〜$16の低コストでFIPS 140-3認証済みHSM保護を実現。IAM/CloudTrailによる監査機能も標準搭載。コスト意識の高いチームに最適。

3 スタートアップ / 個人プロジェクト

推奨: Safe + Turnkey

Safe の無料マルチシグで基本的なガバナンスを確保し、Turnkey の低コスト署名（$0.01〜$0.10/署名）で鍵保護を実現。パスキー認証にも対応しており、エンドユーザー向けの組み込みウォレット用途にも展開可能。開発スピードとセキュリティのバランスが良い。
